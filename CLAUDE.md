# wesley-corpus

Searchable archive of Wesley writings (24,656 passages). FastAPI + Jinja2,
deployed to Fly.io as `wesley-corpus`, served at `corpus.historyofmethodism.com`.

## Fly account

The `wesley-corpus` Fly app lives under **gryngamour@gmail.com** — NOT
`littleeachdayapp@gmail.com` (which owns the Wroot Labs Vercel projects).
Run `fly auth login` with the right email before any `fly deploy` /
`fly secrets` / `fly ssh` work.

## Deploy

```sh
fly deploy -a wesley-corpus
```

Uses `Dockerfile.lite`. Two machines in `iad`, auto-stop/start enabled,
min-running 0.

**SWI v2 (LLM judge) needs a secret set once before its first deploy:**
`fly secrets set ANTHROPIC_API_KEY=... -a wesley-corpus`. Without it, SWI
silently runs the v1 lexicon fallback (`"engine": "lexicon-fallback"` in the
response) — no error, just degraded scoring. See
`strangely_warm_index/V2-HANDOFF.md` for the full design.

## Data pipeline

`raw/` → `process_corpus.py clean` → `cleaned/` → `process_corpus.py chunk`
→ `chunked/passages.jsonl` → `clean_corpus.py` → `chunked/cleaned_passages.jsonl`
(the file `web_app.py` actually loads).

Themes are tagged by `tag_passages.py` writing back to `passages.jsonl`.
Scripture index regenerated by `extract_scripture_references.py`.
SWI scoring is on-demand at request time — no precomputed cache.

After any chunk-level changes, always re-run `clean_corpus.py` so the
serving file stays in sync.

## Known gotchas

- Scripture-reference extraction is regex-based and misses Wesley's
  bare-verse-number citation style ("3. God appeared…" instead of
  "Genesis 35:3"), so `jw-notes-nt` and `jw-notes-on-old-testament`
  contribute near zero to `scripture-index.json` despite being mostly
  scripture references. Heuristic enhancement is a future task.
- Several legacy scripts have hardcoded paths pointing at the pre-2026-04-05
  iCloud Documents location (`tag_passages.py`, `extract_scripture_references.py`
  already patched; others may not be).

## Journal OCR cleanup — DONE 2026-07-07 (Phase 1, see plans/2026-07-07-swi-v2-ocr-cleanup-verification.md)

`scripts/journal_ocr_fixes.py` applies running-header strip + the garble
table below to the 4 raw single-file journal sources (`journal-vol1-3`,
`journal-vol4-7`, `journal-1760-to-1773`, `journal-1773-to-1776`) as a step
after `process_corpus.py`'s generic `clean_text()` — deliberately NOT wired
into that shared function, so it can't touch any other source. Running
headers: 584 → 0 header-containing passages corpus-wide. Verified via the
Phase 3c sentinel suite (`scripts/check_sentinels.py`): no regressions,
and the two directly-affected sentinels improved (Aldersgate wording
0.66→0.98, "who shall convert me" 0.66→0.92). Skipped per the plan: bare
`ot`→`of` (too ambiguous without a dictionary gate) and `'7`-style bleed
was instead handled by a general "strip apostrophe before a digit" rule
(safe — no legitimate use of apostrophe-then-digit in this corpus).

Known noise_report.py gap found along the way: its dictionary lacks some
irregular verb forms (e.g. "began"), so they appear as false-positive
"non-word" offenders — not real corpus damage, just a measurement blind
spot in the Phase 0 tool. Worth extending `PERIOD_SUPPLEMENT` in
`scripts/noise_report.py` if the noise metric needs to be exact later.

The journal volume(s) under `raw/john-wesley/journal-vol*.txt` were heavily
OCR-damaged in systematic, mechanically reversible ways. Discovered
2026-05-27 while extracting the Georgia journal (lines 644–3660) for the
`wroot-press/wesley-journals` adaptation.

Confirmed patterns in `journal-vol1-3.txt` (likely present in vol4-7 too):

- Day-name garbles: `Tvrspay` → `Tuesday`, `Wepnespay` → `Wednesday`,
  `Saturpay`, `Frwway`, `Toespay`, `Monpay`, `Sunpay`, `Thurspay`. The
  `p` is consistent OCR-misread of italic-`d` in the source font.
- Proper-name garbles: `Inghart`/`Inghan` → `Ingham`, `JOTN` → `JOHN`,
  `WESLLY` → `WESLEY`.
- Word-level: `rot` → `not`, `aot` → `not`, `ot` → `of` (this one risky
  in context), `tlie` → `the`, `[was` → `I was`, `'7` → `7` (stray
  quote-mark bleed onto day numbers).
- Running headers: lines like `feb. 1738.] REV. J. WESLLY'S JOURNAL R 61`
  embedded mid-page; strippable with a regex matching
  `REV\.?\s*J\.?\s*WESLEY.*JOURNAL.*\d+`.
- Bare page-number lines.

A working extract + cleanup script lived briefly at
`~/wroot-press/wesley-journals/raw/_clean_ocr.py` (since deleted after
producing the journals project's clean copy). Pattern table from that
script can be lifted directly. Reference output:
`~/wroot-press/wesley-journals/raw/_georgia-journal-emory-clean.txt`.

**Impact on corpus:** Passages from the Georgia and later journal are
searchable but contain visible OCR garbage; SWI scoring is probably
slightly depressed where word-recognition fails. Cleanup is non-urgent
(corpus is functional) but high-leverage — one cleanup pass + re-chunk
+ re-tag + re-deploy would noticeably improve journal passage quality.

When tackling:
1. Apply the substitution table to `raw/john-wesley/journal-vol*.txt`.
2. Re-run the pipeline: `process_corpus.py clean` → `chunk` →
   `clean_corpus.py` → `tag_passages.py` → `extract_scripture_references.py`.
3. `fly deploy -a wesley-corpus` (under `gryngamour@gmail.com`).
4. Spot-check by searching `corpus.historyofmethodism.com` for
   "Tuesday" and confirming Georgia-period entries surface.
